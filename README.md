# YAMLIST — v0.8

設計仕様書 v0.1 ＋ 追加仕様（子タスク連続作成・階層内優先順位）の実装。
ローカル完結・オフライン動作の Android アプリ。
プロジェクト配下にタスクを無限にネストでき、**葉タスクのみ**を対象に件数進捗と重み進捗を集計する。

言語は日本語／英語の2言語対応（アプリ内切替＋端末ロケール追従）。メッセージ、YAMLの検証エラー、PDFチェックシート、サンプルデータまで選択中の言語で表示する。

## 検証状況

v0.8 は、JVM 上で進捗計算・YAML処理の単体テストを実施した。Android アプリ全体のビルドと実機確認は未実施（実機確認は引き継ぎ）。

v0.7 は、JVM 上で進捗計算・YAML処理の単体テストを実施した。Android アプリ全体のビルドと実機確認はこの版ではまだ行っていない。

v0.6 は Android アプリ全体のビルドと単体テストを実施し、A403SH で重み・進捗対象の一括保存に関する計測テスト4件を通した。実機画面で一覧表示、進捗対象の切り替えと数値入力による合計・割合の即時更新、キーボード表示中の保存ボタン、未保存変更の破棄を確認した。

DBスキーマは v3 のまま。過去版からのデータ移行では `fallbackToDestructiveMigration()` が設定されているため、旧アプリのデータはバックアップZIP経由で移す。

## ビルド手順

1. Android Studio（Koala 以降 / AGP 8.5 対応版）で `Yamlist/` を開く。
2. JDK 17 を使う（`compileOptions` は 17）。
3. 初回同期で `libs.versions.toml` の依存が解決される。ネットワーク（Maven Central / Google Maven）が必要。
4. `app` 構成を実機または API 26 以上のエミュレータで Run。
5. 初回起動時にサンプルプロジェクト（「サンプル現場 / Sample Site」）が1件シードされる。

CLI で回すなら:

```
./gradlew :app:testDebugUnitTest          # 単体テスト（進捗・YAML）
./gradlew :app:connectedDebugAndroidTest  # DAO テスト（要エミュレータ）
./gradlew :app:assembleDebug              # APK
```

## アーキテクチャ

MVVM + 単方向データフロー。層は3つ。

- **domain/** — Android 非依存の純 Kotlin。`Task` / `Project` / `TaskNode`、木構築 `TaskTreeBuilder`、進捗集計 `ProgressCalculator`。ここが仕様の心臓部で、単体テスト対象。
- **data/** — Room（`entity` / `dao` / `YamlistDatabase`）、`YamlistRepository`（ドメイン⇔エンティティ変換を内部化し、VM にはドメイン型だけを見せる）、ファイル入出力（`yaml` / `pdf` / `backup`）。
- **ui/** — Jetpack Compose 画面＋ViewModel。画面ごとに `*Screen.kt` と `*ViewModel.kt`。Navigation Compose でルーティング。

DI は Hilt。DB とサービスは `@Inject` コンストラクタ注入。`AppModule` は Room の `YamlistDatabase` だけを `@Provides` する。

### 進捗計算の要点（仕様 §8）

- 集計対象は**葉タスクのみ**。親は自分の重み・件数を一切持ち込まない（二重計上しない）。
- `weight <= 0` の対象は**分母・分子の両方から除外**。
- 完了していないタスクは**分母には入るが分子には入らない**。「保留」状態は v0.8 で廃止した（旧データは未完了として扱う）。
- 対象0件なら 0%。表示整数は四捨五入（half-up）。
- 論理削除タスクはどこでも除外。

### 削除（仕様 §18.2）

タスクのサブツリー削除は再帰 CTE（`WITH RECURSIVE`）1文で論理削除。確認ダイアログ用の配下件数は `countDescendants` で別取得。

### YAML 入出力（仕様 §15）

インポートは **2つの記法**を受け付ける。

**(a) 正式スキーマ** — `schema_version` / `project.title` / `tasks[].title` の再帰。重み・状態・マーク・期限まで全て指定できる。エクスポートはこの形式で出る（往復可能）。

**(b) 構造記法** — 名前を入れ子にしただけの自然な書き方。PC で現場構成をガッと書くための入口。

```yaml
案件名: 昭和田中生命ビル新築
種別: 工事
階層:
  1階:
    東:
      自動制御盤:
        - CP-01-01
      空調機:
        AHU-01-01:
          VAV:
            - VAV101
            - VAV102
        AHU-01-02:
      中央監視:
```

変換規則（`StructureYamlConverter`）:

- マップのキー → タスクのタイトル。値を再帰して子にする。
- リストの文字列要素 → それぞれ葉タスク。
- リストの中のマップ → 同じ階層に展開（`- AHU-02: [VAV1]` が通常キーと同じ扱いになる）。
- 値が `null`（`中央監視:` のようにキーだけ） → 子を持たない葉タスク。
- 案件名は `案件名 / 現場名 / 物件名 / プロジェクト名 / title / project_name` のいずれか。`種別` は説明欄に畳み込む。
- ツリーの入り口は `階層 / 構成 / 構造 / tasks / hierarchy / structure / items` のいずれか。無ければメタ情報以外の全キーを構造とみなす。

**構造記法で取り込まれるのは階層とタイトルだけ**。重み=1・状態=未完了の素の状態で入るので、そこからアプリ側で肉付けする前提。

判別は自動で、`schema_version` があるか `project` が `title`/`tasks` を持てば正式スキーマ、それ以外は構造記法として変換する。どちらも同じ画面（SCR-06）の同じ流れで読める。

その他:

- `YamlImporter.parse()` が SnakeYAML でテキスト→オブジェクトグラフに変換し、`StructureYamlConverter.normalize()` で正規化、`mapAndValidate()` が検証と写像を担う。**検証・変換ロジックはパーサ非依存**で単体テストできる構造。
- `schema_version` / タイトル / `progress_mode` / `status` / `weight` / `planned_month`(YYYY-MM) / 日付 / `completed_at` / UUID 重複 / 件数・深さ上限を検証。
- インポートは1トランザクション。失敗時は全ロールバックし、既存データを壊さない。
- モードは NEW / UUID_UPSERT / DUPLICATE。

**order キー（追加仕様 §2.9）**

- 入力時：`order` があれば尊重する。無ければ配列順から 1000 刻みで採番する。
- 出力時：標準では省略する（配列順が既に順序を表すため）。`YamlExporter.export(..., includeOrder = true)` で明示出力できる。

### 子タスク連続作成（追加仕様 §1 / SCR-10）

親タスクを選び、複数行テキストで子タスクを一括登録する。1件ずつ画面を開き直す手間を省くための機能で、YAML を持ち出すほどでもない十数件規模の登録を想定している。

起動口はタスクツリーの長押しメニューとタスク詳細画面の2か所。

**行の扱い**（`BulkTitleParser`）

| 入力 | 扱い |
|------|------|
| 通常文字列 | 1件のタイトル |
| 空行 | 無視 |
| 前後の空白 | trim |
| タブ・全角スペースのみ | 空行扱い |
| 先頭の `- ` / `・` / `* ` | 除去（画面のスイッチでOFF可） |
| 重複タイトル | 許可（現場の反復確認項目は普通に重複する） |
| 先頭の番号 | **除去しない**（`1.` が機器タグの一部でありうるため） |

**共通属性** — 重み・マーク・色・予定年月・予定日・ステータス・進捗計算対象・固定コメントを1セット指定し、全件に同じ値を適用する。個別の差分は作成後にタスク編集画面で付ける。

**上限** — 一度に100件、1タイトル200文字。超過時はエラーを出し、YAML入力を案内する。

**保存** — `YamlistRepository.addChildrenBulk()` が1トランザクションで処理。1件でも失敗すれば全件ロールバックし、中途半端な状態を残さない。親が削除済み・別プロジェクト所属の場合もここで弾く。

### 階層内優先順位・自動採番（追加仕様 §2）

同一階層内の並び順そのものが作業手順を意味することがあるため、順序を安定させる。

**採番**（`TaskOrdering`）

- 単位は階層ごとに独立。ルートタスク同士、同じ親を持つ子タスク同士で別採番。
- 新規は「その階層の最大 displayOrder + 1000」。空の階層なら 1000。
- 1000刻みにしてあるのは、後から間に差し込む余地を残すため。
- 手動並べ替え後は、その階層だけを 1000, 2000, 3000... に再採番（`reorderSiblings`）。
- 親の変更はドラッグではなくタスク編集画面から行う（初期版の方針）。

**表示番号**（`HierarchyNumbering`）

`1` / `1.1` / `2.3.1` の階層番号は **DBに保存しない**。親子関係と displayOrder から表示時に生成する。そのため削除や並べ替えをしても番号の振り直し処理が要らず、常に画面の見た目と一致する。

**順序の一貫性** — 画面・PDF・YAML出力はいずれも displayOrder 昇順。`TaskTreeBuilder` が構築時にソートするので、経路によらず同じ並びになる。

### ツリー表示の操作（v0.3 追記）

**一括展開・折りたたみ** — ヘッダ直下に4つのボタンを置いた。

| ボタン | 動作 |
|--------|------|
| 全展開 | すべての枝を開く |
| 全折畳 | すべての枝を閉じ、ルートだけにする |
| 1層開く | まだ閉じている中で**最も浅い**層を開く |
| 1層閉じる | いま開いている中で**最も深い**層を閉じる |

現場構成は深くなりがちで「全展開」だと画面に収まらないため、1層ずつ出し入れできるようにしてある。端まで行った状態でさらに押しても何も起きない（no-op）。

**全階層のチェックボックス** — 葉だけでなく親タスクにもチェックボックスを付けた。親は配下の状態を三状態で示す。

| 配下の状態 | 表示 |
|------------|------|
| すべて完了 | チェック済み |
| 一部完了 | 中間（ハイフン） |
| 未着手／対象なし | 未チェック |

親のチェックを付けると配下すべてを完了に、外すと配下すべてを未完了にする（既存の `setSubtreeStatus` を利用）。**進捗計算は葉のみという原則は変えていない** — 親のチェックはあくまで配下をまとめて操作するショートカットで、親自身が分母・分子に入ることはない。

**階層内番号** — 表示は `2.3.1` のようなフルパスではなく、その階層内での番号（`1`）だけにした。祖先はインデントで分かるため、深い階層でフルパスを出すと行が読みにくくなるだけだった。内部では従来どおりフルパスを生成しており（`TreeRow.number`）、表示時に末尾の要素を取り出している（`TreeRow.localNumber`）。PDF の階層番号は印刷物では通し番号が有用なため、フルパスのまま変更していない。

### タスクの並べ替え・移動（v0.4 追記）

**階層内での順序変更** — 長押しメニューに「上へ移動」「下へ移動」を追加した。同一階層の隣接タスクと displayOrder を入れ替える（`YamlistRepository.moveSibling`）。端まで行くと何もしない。

**階層の移動** — 長押しメニューの「他の階層へ移動」から SCR-11（タスクの移動）を開く。プロジェクト内の全タスク＋「プロジェクト直下」を移動先として一覧表示し、選ぶと即座に移動する。**自分自身・自分の配下には移動できない**（サイクル防止）。移動先の階層の末尾（既存タスクの後ろ）に1000刻みで追加される。

### 親削除で子を1階層昇格（v0.4 追記）

長押しメニューに「このタスクのみ削除（子は残して1階層昇格）」を追加した。通常の削除（配下ごと削除）とは別の操作で、対象タスク**だけ**を削除し、直接の子タスクは対象タスクの親（祖父母階層）へ付け替える。子同士の相対順序は保ったまま、その階層の既存タスクの後ろに追加される。確認ダイアログで「配下の子タスクは1階層上がり、同じ順序のままプロジェクトに残ります」と案内する。

**実装上の注意（バグ修正）** — この機能を作る過程で、`maxChildOrder`（採番の基準値を取るクエリ）が論理削除済みタスクを除外していないという既存バグ（v0.3から存在）を見つけて直した。直さないと削除済みタスクがその階層の採番上限を永久に押し上げ続ける。あわせて、昇格削除の処理順序を「対象タスクを先に削除 → その後で子を再採番」に変更した。先に子を動かしてしまうと対象タスク自身がまだ自分の階層の一員として数えられ、無駄に1ステップ分ずれた採番になるため。

### コメントの取消線・削除・マーク（v0.4 追記）

- コメントをタップすると取消線のON/OFFを切り替えられる（`TaskCommentEntity.struck`）。削除ではなく「もう関係ないが記録として残す」ためのもの。
- 各コメントに削除アイコンを付けた（論理削除）。
- コメントが1件以上あるタスクには、ツリー画面のマークの隣に💬を表示する（`YamlistRepository.observeCommentCounts()` でタスクごとの件数を集計）。取消線付きコメントもこのマークの対象に含まれる（記録として存在する限り目印を出す）。

### PDF（仕様 §16, §27.5）

`ChecklistPdfGenerator` は `android.graphics.pdf` による**実描画**。画面のスクリーンショットではない。階層番号・チェックボックス・「備考：___」記入線・ページ跨ぎ保護（行と備考を分割しない）を持つ。

### バックアップ／復元（仕様 §19）

`BackupManager` が ZIP（`manifest.json` / `projects.yaml` / `comments.json` / `settings.json` + SHA-256）を生成。復元は **DB に触れる前に `inspect()` で検証**し、`restore()` は全置換をトランザクション内で行う（失敗時ロールバック）。

## 2言語対応と既知の制限

- 画面ラベルは全て `R.string` に外出しし、`values/`（英語・デフォルト）と `values-ja/`（日本語）に定義。
- アプリ内の言語切替は `LocaleHelper`（SharedPreferences）＋ `attachBaseContext` で全 API レベルに効く。設定画面で システム／日本語／English を選ぶと `Activity.recreate()` で即反映。
- Android 13+ 向けに `locales_config.xml` も同梱（システム設定のアプリ別言語に出る）。

- ViewModel のメッセージは `UiText`（文字列リソースIDと引数）で持ち、画面側で選択中の言語に変換する。
- YAML の検証エラーは `YamlErrorKind`（種類）と引数で返し、`YamlErrorText.kt` が文字列リソースに変換する。取り込み処理自体は Android に依存しない。
- PDF チェックシートの文言と日付書式は、印刷画面から `ChecklistPdfGenerator.Labels` として渡す。
- サンプルYAMLは `res/raw/`（英語）と `res/raw-ja/`（日本語）に置く。
- 初回サンプルデータは初回起動時の端末の言語で作成する（作成後に言語を切り替えても、データの文言は変わらない）。
- 構造記法の取り込みで自動生成する文言（無題時のプロジェクト名、「種別」）は、YAML のキーが日本語なら日本語、そうでなければ英語になる。
